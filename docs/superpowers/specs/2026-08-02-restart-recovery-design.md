# アプリ再起動からの自動復帰 設計書

- 日付: 2026-08-02
- 状態: 設計確定（実装前）
- 対象: `tools/autolive.py` の `detect()` / `_loop()`、`assets/templates/`

## 1. 背景

イベント周回中、毎日 4:00 前後に「**データ更新のためタイトルへ戻ります**」が割り込む。
アプリはタイトルへ戻り、そこから先を `autolive.py` が認識できないため、
**未知画面に 25 秒停滞 → `stop_reason="unknown_screen"` で安全停止**して周回が終わる。
`run_until.sh` は「繋がっているのに止まった」を検知して runner ごと終了するので、
朝まで無人で回すつもりが 4:00 で止まる。

ダイアログ自体は既に処理できている（`dataupdate` 状態、`assets/templates/data_update.png`
の中身がまさにこの文言）。**欠けているのはタイトル画面から先の導線だけ**。

## 2. 実機で確認した導線（2026-08-02 実測）

ウィンドウ 671×348、イベント「BUDDY Night NARRATIVE」（開催 2026/07/30 17:00 - 08/06 16:59）。

| # | 画面 | 操作 | 現状 |
|---|---|---|---|
| 0 | 「データ更新のためタイトルへ戻ります」 | はい | **実装済み**（`dataupdate`） |
| 1 | 起動時の注意書き（下部に「TAP SCREEN」） | 中央下をタップ | 未対応 |
| 2 | BANDAI NAMCO スプラッシュ（約6秒） | 待つ | 未知画面だが停滞タイマ内 |
| 3 | タイトル（背景は動画、「TAP SCREEN」が点滅） | 中央下をタップ | 未対応 |
| 4 | Now Loading（白飛び、約8秒） | 待つ | 未知画面だが停滞タイマ内 |
| 5 | **お知らせ** ダイアログ | 右上の × | 未対応 |
| 6 | ホーム | **左（ベージュ）の EVENT リボン** | 未対応 |
| 7 | イベントトップ | 「イベント楽曲」 | 未対応 |
| 8 | **休憩時間の確認ダイアログ**（休憩中のみ） | **いいえ → 停止** | 未対応 |

### 2.1 休憩時間ダイアログ（新しい安全停止条件）

イベントトップで「イベント楽曲」を押すと、休憩時間中は次が出る。

> 休憩時間中はイベントPtを獲得することができません。よろしいですか？
> 休憩時間: 08/02 16:00 ~ 08/02 23:59
> 　［いいえ］　［はい］

**「はい」を押すと Pt がゼロのまま LIFE を消費する。** きなこパン枯渇時のステラ誤消費と
同種の「気づかず損をする」画面なので、**必ず「いいえ」を押して停止する**。

休憩時間帯は**ゲーム内のユーザー設定**（表示の横に「設定」ボタンがある）。
固定の時間帯を前提にしてはいけない（`docs/navigation.md` 参照）。

### 2.2 ホームの EVENT リボンは2つある

ホーム右側にリボンが2つ並ぶ。**ラベル帯がベージュの方**が累計イベント（周回対象、
ユーザー確認済み）。もう一方は青いラベル帯。下段のバナーは数秒ごとに切り替わる
カルーセルなので照合に使えない。

`CLAUDE.md` 絶対規則3 の「ホーム**左下**のイベントリボン」は現在の UI と一致しない
（実測では右側）。規則の意図（LIVE ボタンから入るな）は変わらないので、
文言だけを実態に合わせる。

## 3. 方針

**`autolive.py` の FSM に復帰用の状態を追加する。** 新しいプロセスもスクリプトも作らない。

中断も復帰も「画面を認識して押す」という同じ問題であり、`autolive.py` は既にそれを
毎フレームやっている。`supervise_autolive.sh` と `run_until.sh` は無改造で、
既存の安全停止・スクショ保存・停滞タイマがそのまま効く。

検討した代案:

- **別スクリプト `tools/ops/return_to_event.py`**: プロセスの生殺与奪を増やす。
  この領域は過去に二重起動事故を起こしている（`tests/test_ops_ownership.py`）。
  `detect()` を二重に持つことにもなる。**採らない**
- **LLM ナビの自動起動**: `CLAUDE.md` の役割分担（実操作はスクリプト）に反し、API に依存する。
  ユーザーが「スクリプト化が改善対象」と明示している。**採らない**

## 4. テンプレート

既存の `assets/templates/tap_screen.png` や `assets/screens/event_top/event_songs_btn.png` は
**現在の画面に当たらない**（実測 0.54 / 0.42）。イベント装飾と UI 変更で崩れている。
実機フレームから切り直す。

| キー | ファイル | 切り出し元 | しきい値 |
|---|---|---|---|
| `title` | `title_tap.png`（注意書きの「TAP SCREEN」） | 起動直後 | 0.85 |
| 〃 | `title_tap_dark.png`（タイトルの「TAP SCREEN」） | タイトル | 〃 |
| `news` | `news_title.png`（ヘッダ「お知らせ」） | お知らせ | 0.85 |
| `home` | `home_event.png`（ベージュの EVENT ラベル帯） | ホーム | 0.85 |
| `eventtop` | `eventtop_songs.png`（「イベント楽曲」ボタン） | イベントトップ | 0.85 |
| `breaktime` | `breaktime.png`（本文「休憩時間中は…」） | 休憩ダイアログ | 0.85 |

`title` は `load_templates()` の variant 機構（`<stem>*.png` を glob）で2枚を同じ状態に束ねる。
タイトルの「TAP SCREEN」は点滅するので、消えている瞬間は 0.507 で未検出になるが、
ループが次のフレームで拾い直す。

**イベント固有の絵は1枚も使わない。** バナーの絵柄は毎イベント変わるが、
「EVENT」ラベル帯・「イベント楽曲」の文字・ダイアログ本文は変わらない。

## 5. `detect()` の判定順（順序が仕様）

`resendresult` の直後、`liveassist` より前に挿入する。すべて `cardx` より前に置く
（お知らせ・ホームはシアン〜緑の帯を持ち、`detect_card_x` に誤検出されうるため）。

```
… lifeshort … resumelive → dataupdate → resendresult
  → breaktime → title → news → eventtop → home
  → liveassist → formation → cardx → …
```

**`breaktime` は必ず `eventtop` より先。** 休憩ダイアログは「イベント楽曲」ボタンを
背後に残したまま出るため、`eventtop_songs` が 0.943 で当たってしまう。順序を逆にすると
ダイアログの裏のボタンを押し続けて停滞する。

## 6. ハンドラ

すべて**テンプレのマッチ位置を基準にクリック**する。固定のウィンドウ相対座標は使わない。

| 状態 | 操作 | 待ち |
|---|---|---|
| `title` | マッチ位置（TAP SCREEN）をクリック | 2.5秒 |
| `news` | ヘッダから `ANCH_NEWS_CLOSE=(207.5, 6.5)` px で × | 1.5秒 |
| `home` | マッチ位置（EVENT ラベル）をクリック | 2.0秒 |
| `eventtop` | マッチ位置（イベント楽曲）をクリック | 2.0秒 |
| `breaktime` | `ANCH_BREAK_NO=(-73.0, 100.0)` px で「いいえ」→ **停止** | — |

オフセットは実機フレーム上でテンプレのマッチ位置と目標位置を実測して求めた。
`docs/navigation.md` に残る `(0.7015, 0.840)` のような固定座標は使わない。

## 7. 安全策

- **未知画面ではクリックしない**（絶対規則6）。従来どおり安全停止＋スクショ保存
- `breaktime` は `stop_reason="break_time"` で**安全停止**（終了コード 42）。
  supervisor は再起動せず、`run_until.sh` も終了する。休憩中に回しても無意味なので正しい
- **復帰の試行回数に上限を設ける**。`title` を踏んだ回数が `MAX_RECOVERS`=3 を超えたら
  `stop_reason="recover_loop"` で停止する。同じ所を延々回るのを防ぐ
- 各状態の停滞は既存の `STUCK_STOP_SEC`=25 秒がそのまま効く

## 10. 検証の限界

- 実機で通しで確認できるのは**タイトル → イベントトップまで**（休憩明けを待って
  楽曲選択まで確認する）
- 4:00 の実際の割り込みからの復帰は、**4:00 になるまで検証できない**
- ログインボーナス等、今回出なかったポップアップが 4:00 に出る可能性がある

**失敗しても現状と同じ挙動（安全停止＋スクショ保存）で、悪化しない。** 通れば本番検証完了、
通らなければ `/tmp/i7dbg/` にスクショが残るので次回確実に直せる。

## 11. 反映の段取り

0:00 は現行コードで周回を開始してよい。実装が終わったら、**ライブの合間に autolive の
子プロセスだけを kill** すれば supervisor が新コードで再起動する
（`docs/operations.md`「打鍵パラメータのチューニングを反映する方法」）。
