# ノーツ追跡エンジン 開発ノート（branch: note-tracking-engine）

現行 `autolive.py` の打鍵は「到達点(円ROI)の明るさスパイクでタップ」。限界:
到達点ではノーツが白く**色/種別が判別不可**、タップ波紋が長押しと交絡。
本エンジンは **中心スポーンで検出 → 色/形で種別判定 → レーン追跡 → 到達タイミングで
種別別操作**（タップ/長押し/フリック/スライド）を狙う。実装は `tools/note_engine.py`。

## 確定したフィールド模型（実機観測）

- **このゲームは4レーン**（中央レーンは無い＝SCORE表示と重なる）。現行 `CIRCLES` は5要素で
  中央(index2)はダミー。本エンジンの `LANES` は中央を除く4箇所（左端/左下/右下/右端）。
- ノーツは**上部中央スポーン**（content相対 ≈ (0.49, 0.28)）から各レーンへ**放射状に移動**。
- 中盤(y≈0.45)に淡いレーンガイドの弧がある。

## 現状（このコミット時点）

`note_engine.py`:
- `detect_notes(frame, win, content)`: 明るい画素(min>110)をプレイ帯(y 0.05–0.62)で二値化し
  連結成分でブロブ抽出。各ブロブの rgb・色分類・レーン割当を返す。
- `classify_color(rgb)`: 緑/赤/青/白の暫定分類。
- `assign_lane(cx,cy)`: スポーンからの方向に最も近いレーンを選ぶ。
- CLI: `viz <frame> [out]` / `scan <dir>`。

## 観測で判明した課題（次の作業）

1. **静止物の誤検出**: PAUSEボタン・レーン円のフチ・画面端を拾う。
   → **時間追跡で「フレーム間で動く blob だけ」を残せば除外できる**（最重要の次ステップ）。
2. **中空リングの大ノーツが未検出**: area/明るさ閾値の調整、リング(円環)検出（Hough等）の検討。
3. **色判別**: スポーン付近でも通常ノーツは白。色が付くのは特殊ノーツ(緑/赤/青)のみで稀。
   背景(キャラカード/ピンク演出)と混同しやすい。スポーン直後の数フレームで彩度ピークを取る等。
4. **レーン割当**: スポーン直後は方向が未分化で不正確。数フレーム追跡して速度ベクトルで判定する。

## 実装ロードマップ

- [x] フィールド模型（4レーン/スポーン）確定、ブロブ検出、可視化CLI
- [ ] **トラッカー**: blob をフレーム間で対応付け（最近傍）、軌跡・速度を推定。静止物を除外。
- [ ] **レーン確定＆到達予測**: 速度ベクトルから target レーンと到達時刻(ETA)を推定。
- [ ] **種別判定**: 追跡開始時(スポーン)の色/形で tap/hold/flick/slide を分類（色は彩度ピーク、
      形はリング径/尾の有無）。較正用に種別が分かるフレームを収集。
- [ ] **操作ディスパッチ**: ETAに合わせて autolive の HID 入力で実行
      （tap=現行、hold=down保持+drag、flick=down→枠外drag→up、slide=進行方向drag）。
- [ ] **autolive 統合**: `--engine track` 等で切替。**クリア信頼性を絶対に落とさない**ことを
      各段階で実機検証（farmingはクリアが目的でスコアは副次）。フォールバックは現行タップ。

## 検証メモ

- 観測フレーム: 連写は `/tmp/i7track/`（密 ~0.05s）、`/tmp/i7notes/`（疎）。
- 静止物（PAUSE/円フチ/端）は動かないのでトラッカー導入で大半が解決する見込み。
- **リスク**: 低解像度(671×348)・中空リング・彩色背景・実時間制約。現行タップは既にEASYを安定
  クリア&SS。新エンジンが farming で上回る保証はない。スコア用途/高難度用途で価値が出る想定。
