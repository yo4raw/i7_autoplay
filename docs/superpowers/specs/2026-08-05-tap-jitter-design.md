# タップ座標ジッター設計

- 日付: 2026-08-05
- 対象: ライブ中の打鍵（`tools/autolive.py` の `timing` / `rotate` 両モード）
- 目的: 統計的な手法によるボット判定への耐性を上げる

## 背景

ライブ中の打鍵は `click_content(*CIRCLES[i])` で行っており、**着弾点が毎回まったく同じ
4 点**になっている。散らばりは厳密にゼロで、入力ログを統計的に見れば人間の操作と即座に
区別できる。本設計は着弾点に人間らしい散らばりを持ち込む。

### 検討したが採用しなかった案

当初は「ランダムにミスを発生させる」方向で検討したが、実測値を確認して取り下げた。

`docs/operations.md` の到達水準（Don't Analyze Me / EASY+ / ブースト3倍）:

| 指標 | 値 |
|---|---|
| PERFECT / GOOD / BAD / MISS | 17 / 158〜160 / 2〜4 / 5 |
| 総ノーツ | 約 184 |

- **反応遅延の揺らぎ**: `docs/architecture.md` に「画面キャプチャ遅延(±60-100ms)で
  PERFECT 安定は不可・GOOD帯中心」とあるとおり、遅延には既に ±60〜100ms の自然な
  揺らぎが乗っている。注入する揺らぎは既存の揺らぎと二乗和で合成されるため、σ を 50ms
  足しても `√(80² + 50²) ≈ 94ms` にしかならず分布の形はほとんど変わらない。一方で裾は
  18% ほど広がり BAD/MISS は倍近くになり得る。**形が変わらないのにミス予算だけ使い切る**
  ため不採用。
- **ノーツの見送り**: 制御は確実だがスコアとグレード（SS 目標）を直接削る。今回は不採用。

結果として本設計は**意図的なミスを一切注入しない**。ユーザー指定のミス率上限 3% は
**消費ゼロ**である。

### スコープ外

- 反応遅延の揺らぎ、ノーツの見送り（上記の理由）
- カーソルの移動経路（中間点が別レーンに入ると誤入力になり得るためリスクが高い）
- 周回セッション層（周回間隔・休憩・曲選択）の揺らぎ。run-to-run の一貫性（同じ曲・
  同じスコア帯 33.8〜34.3万・同じ 83 秒）は残る最大のボット信号だが、今回のスコープ外

## 打鍵地点の棚卸し

`CIRCLES` を参照して入力を送っている箇所は以下がすべて。

| 箇所 | 行 | 内容 |
|---|---|---|
| 通常タップ | `autolive.py:1162` | `click_content(*CIRCLES[i])` |
| キープアライブ | `autolive.py:1219` | ノーツ無し区間の PAUSE 防止タップ |
| フリック | `autolive.py:868` | ドラッグ開始点 |
| ホールド | `autolive.py:1045,1049,1069,1073,1090,1094,1122,1139,1148` | `_press(... "down"/"move"/"up")` |
| rotate（保険） | `autolive.py:1607` | 巡回連打 |

### 最重要の制約

**`CIRCLES` は `--auto-circles` によって in-place で書き換えられる**
（`autolive.py:950` の `CIRCLES[:] = matched`）。これはライブ中に何度でも起こり得る
（確定するまで `AUTOCAL_RETRY_SEC` 間隔で再試行し続ける）。

したがってジッター適用点は **`CIRCLES` を毎回読み直さなければならない**。
座標をインスタンス変数などにキャッシュすると、補正が効いた瞬間から古い座標を叩き続ける。

## コンポーネント構成

### 新規モジュール `tools/tap_jitter.py`

```python
class TapJitter:
    def __init__(self, n_lanes, *, bias_sigma, tap_sigma, max_r,
                 rng=None): ...

    def begin_live(self) -> None:
        """レーン別の恒常バイアスを引き直す（ライブごとに呼ぶ）"""

    def offset_px(self, idx) -> tuple[float, float]:
        """レーン idx の、このタップぶんの px オフセット"""
```

`Quartz` にも `cv2` にも依存しない純粋モジュールにする。実機・画面収録権限・
アクセシビリティ権限なしでテストが回る（`note_engine.py` と同じ立ち位置）。

`bias_sigma` / `tap_sigma` / `max_r` は **px 単位**で受け取る。R（リング半径）からの
換算は呼び出し側（`autolive.py`）が行う。モジュール自体はウィンドウ寸法を知らない。

### `autolive.py` の統合点

```python
def _tap_point(self, idx):
    """CIRCLES[idx] にジッターを乗せた content 相対座標を返す。

    CIRCLES は --auto-circles で in-place 更新されるため毎回読む（キャッシュ禁止）。
    """
    xf, yf = CIRCLES[idx]
    if self.jitter is None:
        return xf, yf
    dx, dy = self.jitter.offset_px(idx)
    top, bottom = self.content
    return xf + dx / self.win["w"], yf + dy / (bottom - top)
```

**x と y で正規化の分母が異なる**（x はウィンドウ幅 `win["w"]`、y は内容矩形高
`bottom - top`）。px 空間で等方な散らばりを作ってから変換しないと、着弾点が
楕円状に歪む。

上記の打鍵地点すべてで `CIRCLES[i]` を `self._tap_point(i)` に差し替える。

**検出 ROI には触れない。** `_circle_roi_px()` は素の `CIRCLES` を使い続ける。
ジッターはクリック先だけの話であり、検出は動かさない。この分離を明示的に保つ。

`TapJitter` のインスタンス化はライブ突入時、`begin_live()` は各ライブの開始時に呼ぶ。

## パラメータ

`note_engine.CIRCLE_R_FRAC = 0.05`（円リング半径の目安。SE 実測 ~26px/529w）を基準に、
すべて R との比で表現して端末差を吸収する。

| 項目 | 設定値 | 529w 換算 |
|---|---|---|
| リング半径 R | `0.05 × win_w` | ≈ 26px |
| レーン別恒常バイアス σ | `0.10 R` | ≈ 2.6px |
| タップごとノイズ σ | `0.18 R` | ≈ 4.7px |
| 上限半径 | `0.60 R` | ≈ 15.9px |

合成の散らばりは σ ≈ `√(2.65² + 4.76²)` ≈ 5.4px、最大 15.9px。26px のリングに対して
十分内側に収まる（マージン ≈ 10px）。

### 上限半径の与え方: 切り詰めではなく棄却サンプリング

オフセットは x/y 独立の正規分布で生成する。合計ベクトルが上限半径を超えた場合、
**その半径へ切り詰めてはならない。棄却して引き直す。**

切り詰め方式を実測したところ、**タップの 17% が半径ちょうど 15.9px の円周上に積み上がった**。
恒常バイアスのぶん分布の中心が原点からずれるため、原点中心で計算した棄却率（4.4%）より
はるかに多く境界に当たる。円周上への集中は「毎回同じ 4 点」より不自然な人工物であり、
本機能の目的を正面から損なう。

採用する手順:

1. `begin_live()` で恒常バイアスを引いた後、その長さが `max_r / 2` を超えていたら
   そこへ切り詰める（これにより棄却が必ず有限回で終わる）
2. `offset_px()` は バイアス + ノイズ を生成し、長さが `max_r` 以内なら採用、
   超えたら引き直す（最大 16 回）
3. 16 回とも外れた場合のみ、最後の値を `max_r` へ切り詰める（防御的措置。
   バイアスが `max_r / 2` に制限されているため実際には発生しない）

実測（40 seed × 20k サンプル）: 半径が上限の ±0.05px に入る割合は **0.089%**。
切り詰め方式の 17% から解消された。

### 恒常バイアスを入れる理由

毎タップ平均ゼロのノイズだけだと、着弾点の重心がリング中心に厳密一致してしまい、
それ自体が不自然になる。人間は端末の持ち方に由来する一貫したオフセットを持つ。
レーンごとに独立したバイアスを持たせ、ライブごとに引き直す。

## ホールド中の `move` の扱い

ホールドは `down` のときに一度だけジッターを引き、その点を保持して `move` / `up` は
**同じ点**に送る。`move` ごとに微動させる方が人間の指に近いが、ホールドは実機挙動が
繊細な領域（緑ノーツ対応は実測 3.3% で既定 OFF のまま打ち切られている）なので変えない。

## CLI と既定値

- `--no-tap-jitter` で無効化できるようにする（A/B 用）
- **マージ時点から既定 ON とする。** このリポジトリの慣例では新規の打鍵機能は既定 OFF
  （`--green-hold`）だが、緑ホールドと違ってジェスチャの意味を変えず、リング内に
  収まる限り判定は同じはずであり、かつ「常時かかっていること」自体が機能の目的である

A/B 実測の結果による扱いは次のとおり。既定値の判断を後回しにせず、あらかじめ決めておく。

| A/B の結果 | 対応 |
|---|---|
| MISS 増が誤差範囲（±5%）内 | そのまま既定 ON を維持 |
| MISS が有意に増えた | まず `max_r` を半減（0.60 R → 0.30 R）して再測定 |
| `max_r` を下げても有意に増える | 既定 OFF に落とし、リング当たり判定の実サイズを測り直す |

## エラー処理

| 状況 | 挙動 |
|---|---|
| `--no-tap-jitter` 指定 | `self.jitter = None`。`_tap_point()` は素の `CIRCLES[idx]` を返す |
| `win["w"]` や `content` が未取得 | ジッターを無効化して素の座標を返す（除算エラーを起こさない） |
| `begin_live()` 未呼び出しで `offset_px()` | `RuntimeError`。バイアス未初期化のまま走るのを防ぐ |
| 不正なパラメータ（負の σ、`max_r` ≤ 0） | `__init__` で `ValueError` |

## テスト

`tests/test_tap_jitter.py`（unittest。実行は `.venv/bin/python -m unittest discover -s tests`）。
固定 seed で決定論的に回す。

| # | 検証内容 | 判定基準 |
|---|---|---|
| 1 | タップノイズの σ | **1 ライブ内**の着弾点の σ が `tap_sigma` の **0.90〜1.05 倍** / 20k サンプル |
| 2 | 恒常バイアスの σ | `begin_live()` を 5k 回呼んだときのバイアスの σ が `bias_sigma` の ±10% 以内 |
| 3 | 上限半径 | 全オフセット（バイアス + ノイズの合計）の長さが `max_r` 以内 |
| 4 | 恒常バイアスの持続 | 同一ライブ内で不変、`begin_live()` で変化する |
| 5 | 再現性 | 同一 seed で `offset_px()` 列が完全一致 |
| 6 | レーン独立性 | レーンごとに異なるバイアスを持つ |
| 7 | 座標変換 | `_tap_point()` が x に `win["w"]`、y に `bottom - top` を使っている（分母の取り違え検出） |
| 8 | `--auto-circles` 回帰 | `CIRCLES` を in-place 書き換えたあと `_tap_point()` が新座標に追従する |
| 9 | 無効化 | `--no-tap-jitter` 時に `_tap_point()` が素の `CIRCLES[idx]` と完全一致する |
| 10 | バリデーション | 不正パラメータが `ValueError` を投げる |

テスト 1 の許容が下側に広い（0.90〜1.05）のは、棄却サンプリングが分布の裾を削るため
実効 σ が公称値より小さく出るから。**40 seed × 20k サンプルの実測で 0.925〜0.994** に
収まることを確認済み。上振れは原理的に起こらないので上側は 1.05 で足りる。

この値は `max_r = 0.60 R` を前提とする。`0.45 R` では実効 σ 比が 0.824〜0.932 と
下振れが大きくなり、seed によって結果が大きく変わる。`0.60 R` を採るのはこのため
（リングマージンは 14px → 10px に減るが、26px のリングに対してなお十分）。

テスト 7・8 は既存コードの構造的な罠（座標系の分母違い、`CIRCLES` の in-place 更新）に
対する回帰テストであり、実装より先に落ちることを確認してから実装する。

## 未検証事項

- **リング内なら判定が変わらないことは未確認。** これが崩れると MISS が増える。
  `tools/ops/result_log.py` で `--no-tap-jitter` との A/B を取り、MISS の増加が
  誤差範囲（1 ライブでは ±5%）であることを分布で確認してから既定 ON を確定する
- `--auto-circles` の補正誤差とジッターが同方向に出た場合のマージン。補正が
  数 px ずれた状態で 12px のジッターが同方向に乗ると、リング外に出る可能性がある
- リング半径 `CIRCLE_R_FRAC = 0.05` は検出用の目安値であり、**タップの当たり判定の
  実サイズとは限らない**。A/B で MISS 増が見えた場合はまず `max_r` を下げる
